## 3. In flight: MNE-220, the wordmark

**Problem.** The nav reads `M  NEIA`, not `MNEIA`. A previous session tried `gap: 0` on `.wordmark`
in both stylesheets — that is what is deployed, and it did not work, because the space was never in
the flex gap.

The space is **inside the SVG**. `MneiaMark` used `viewBox="0 0 64 64"` while the M glyph
(`M23 46V25l9 12 9-12v21`, `strokeWidth 6`) only reaches x=44 — 20 units of dead space, **0.375em**.
And the document outline's right edge at x=51 draws a **vertical stroke between the M and the N**, so
no amount of negative margin would ever have fixed it.

**Approach.** An icon cannot double as a letter. Split the jobs:

- `MneiaMark` — unchanged, the boxed document glyph, for favicon / OG / app icon. Still exported,
  currently **no callers** (`apps/site/src/app/icon.svg` is a separate static file).
- `MneiaLetter` — **new**, the bare M on a tight `viewBox="0 0 22 24"`, `strokeWidth 4` (down from 6,
  so it sits at the type's weight rather than heavier), no padding.

**Files changed** (all in `apps/site/src/components/`):

- `MneiaMark.tsx` — added `MneiaLetter` above `MneiaMark`
- `Nav.tsx`, `Footer.tsx` — import and render `MneiaLetter`
- `Nav.module.css`, `Footer.module.css` — `.mark` is now
  `width: 0.66em; height: 0.72em; margin-right: 0.04em; transform: translateY(0.015em)`.
  Footer's `.wordmark` also moved `gap: var(--space-xs)` → `gap: 0`.

**NOT YET DONE — this is where to pick up:**

1. **Visually verify.** The `0.72em` cap height, `0.04em` sidebearing, and `0.015em` baseline nudge
   are calculated, not measured. Run `pnpm --filter @mneia/site dev` and look at both the nav (dark,
   `--primary-on-dark`) and the footer (light, `--primary`). Expect to tune those three numbers.
2. **Decide the M's colour.** It currently stays accent-blue via `--mark-signal` while `NEIA` is
   `currentColor`. That may or may not read as "one word" — it is a founder call. Monochrome is a
   one-line change.
3. **Update `docs/design/mneia.md:141`**, which still says *"No logo exists. The wordmark is set in
   `tagline` as an interim treatment."* Stale — a mark ships in nav and footer.
4. Run `pnpm build && pnpm lint:ci && pnpm format:check`, then commit, push, open a PR with
   `Closes MNE-220`.

## 4. Audit in progress — 14 read-only agents

Launched to answer "what are the next tasks." **Read-only by design** — none of them write, because
of the shared tree. Five have reported. Findings below are theirs, not verified by me.

### Reported

**MNE-101 (hosted API) — the biggest hole.**
- `fetch`/`axios`/`undici` appear **nowhere** in `packages/*/src`. The clients make zero HTTP calls.
- The CLI has four stubbed interfaces rejecting with *"the hosted API lands with MNE-101"*; the MCP
  server takes `ScopedStore` (an in-process DB handle) instead. **Those two contracts are mutually
  incompatible** and reconciling them is the real design work. Neither MNE-101 nor MNE-171 mentions it.
- **MNE-186 is one line.** `assertConnectionEnforcesRls` is written, exported, and called by
  `apps/web` — but `PostgresStoreAdapter.withScope` never calls it. The GUC mechanism itself is
  already correct (transaction-local `set_config(..., true)`, so pooling is safe).
- **`M1_COMMAND_NAMES` (`cli/src/router.ts:4`) structurally blocks `mneia login`/`whoami`** — the
  router throws on any command outside the list. MNE-101 cannot close without editing that line.
- **Correction to something I said earlier: M1 ends Sep 1, not Aug 11** (`ROADMAP.md:77`). Aug 11 was
  the due date on the decision tickets. Estimate: API chunks total 13–18 working days.

**Standing rule 5 is not enforced.** The MNE-51 coverage test **does not exist** — not on `main`, not
anywhere. Four documents claim it is live, including a CI script whose failure text names it. Four of
thirteen §17 events are ever emitted, and `mcp-server/src/bin.ts:89` builds the production emitter
with `sinks: []` — so the shipped binary records zero telemetry to zero destinations. Rule 6 (opt-out,
redaction, no content) is in genuinely good shape by contrast.

**MNE-216 is real but mis-framed.** `assertedBy` cannot defeat standing rule 1 — the supersede arbiter
reads actor kind from the DB (MNE-210 fixed that). It defeats **rule 3**: the writer picks who gets
auto-resolve rights, so a forged row can manufacture an unresolvable human-vs-human standoff. Worse,
**`humanConfirmed` is also caller-supplied** (`types.ts:51` → `postgres.ts:516`) and both MNE-208 and
MNE-216 missed it. Not exploitable today — no surface reaches a live store until MNE-101.
**Separate structural issue needing its own ticket:** no code anywhere provisions an actor with
`kind = 'agent'`, and MCP authenticates with the human's credential — so on the likely MNE-101 wiring,
*every* agent write lands as `human_confirmed = true`. Rule 1 defeated by construction, not by exploit.

**MNE-70 partially done** — `truncateToTokens` is written and tested but **never called** by the
rehydrate pipeline; the shipped strategy is whole-item exclusion. **MNE-71 done.** **MNE-75 partially**
— no p95 evidence exists at all. **MNE-72 not started** (Linear already says Backlog; both events
exist as types only).

**MNE-74 done. MNE-76 done. MNE-77 done** with a caveat (implements §10.1 steps 4–6; step 3,
contradiction detection, is absent from core entirely). **MNE-78 partially** — kind and status filters
work, but there is **no date filter anywhere**, and it is **not semantic**: `search.ts:114-124` never
sets `embedding`, so it is `ILIKE` substring matching. 197/197 mcp-server tests pass.

**MNE-217 has a blocker nobody had spotted.** Both `apps/web` stores call `assertConnectionEnforcesRls`
before every transaction, and the current `DATABASE_URL` role holds `BYPASSRLS`, so the guard throws.
`/projects` is the post-auth landing page and calls `getCurrentAccount()`. **Sign-up will succeed at
Clerk and then `/projects` will 500.** MNE-217's *Done when* cannot be met until MNE-186 lands. Do not
paper over it with `MNEIA_ALLOW_RLS_BYPASS=1`.

Also on MNE-217: `apps/web/next.config.ts` has no `output: 'standalone'` (needed before a Dockerfile
can be written); the Docker build context must be the **repo root**, not `apps/web`, or it cannot see
`packages/core`; and a `/api/health` route added without also adding it to `isPublicRoute` in
`middleware.ts:3` returns a 307 that `curl -f` treats as success — **healthy on a broken app**.

**MNE-215's magnitude is wrong for today, and I repeated it earlier.** Nothing ever writes a non-null
embedding — MNE-54 has not landed, so there is no provider. `embedding::text` on NULL is NULL and the
current wire cost is ~0. The defect is real and the fix is right, but it is **latent until MNE-54**,
not a cost being paid now. Anyone benchmarking to confirm it will find nothing and may wrongly close it.
The fix has a trap: selecting `NULL::text AS embedding` when not requested recreates the same
invisible failure one layer down, because `null` would mean both "none stored" and "not loaded". The
column must be genuinely absent so it is detectable.

**The real latency finding.** One rehydrate issues **10 sequential round trips**. The `Promise.all` at
`rehydrate.ts:198-225` parallelises nothing — a `pg` client serialises its queue and the scoped store
binds one session. Two of those trips are a straight bug: `actorTeamIds` (`postgres.ts:232-241`)
memoises the resolved *value*, not the promise, so three concurrent callers all fire the query. Three
lines to fix. Cross-region is unsurvivable at 10 × RTT — region matching is a precondition, not an
optimisation.

**The CLI is entirely unreachable.** All four commands are wired to an `unwiredApi` stub that rejects
immediately; there is no HTTP client anywhere in `packages/cli/src`. So MNE-81/82/84/85 all fail their
*Done when* on the same blocker. **MNE-83 is 0% built** — and there is no consumer of `mneia_checkpoint`'s
pending queue anywhere in the repo, so even after MNE-101 there is no way for a human to confirm a
pending candidate. `cli.md` calls that "where the moat is collected."

**MNE-63 is half done.** "Never a supersede" is enforced to a very high standard (1440-case generated
table, plus a store-layer guard). But nothing in the codebase ever *writes* `'disputed'`, and
`recordConflict` has **zero production call sites** — a blocked assertion is returned as prose and then
lost. **MNE-67:** w1 is the largest weight and is inert, and the component breakdown is computed then
discarded, so MNE-20 would have nothing to learn from. **MNE-69: genuinely done**, cleanest of the four.

**Public compliance issue.** `apps/site/src/content/legal.ts:52` — the subprocessor table names
**Vercel Inc.** as hosting the API, omits DigitalOcean, and omits **Clerk entirely** despite MNE-166
ruling it the identity processor. That is a live public page. Needs its own ticket.

**MNE-199 looks closeable** — all three of its causes are fixed in merged code while the ticket sits
in Backlog.
